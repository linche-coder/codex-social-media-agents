# 快手创作者服务平台网页流程

目标页面：`https://cp.kuaishou.com/article/publish/video`。该地址默认进入`上传视频`，不要使用带`tabType=3`的全景视频地址。优先使用可见文字、标签、角色和控件状态定位，不依赖固定坐标。

## 进入发布页

1. 单条任务可复用一个已打开的快手`上传视频`页；没有时新建普通网页标签并直接打开目标地址，不要让用户手动打开后台。
2. 确认当前选中的是`上传视频`，不是`上传图文`或`上传全景视频`。
3. 从页面可见状态判断登录。扫码、短信、验证码或安全确认必须由用户完成。
4. 直接使用当前唯一登录账号，并记录顶部可见账号供提交确认和结果汇报；不向用户索取账号字段。

## 多视频页面预分配

已确认快手后台只能保存一个`上次未发布的视频`，内容管理中没有多草稿入口。因此多条视频禁止复用同一个发布页，也禁止上传完第一条后才临时打开第二页。

1. 任务初始化时先统计本次快手视频数量`N`。
2. 在选择任何快手视频文件前，一次性打开`N`个目标上传页；已有一个可用空白上传页时可以计入数量，其余新建。
3. 逐页确认 URL、`上传视频`页签和登录状态，然后按内容顺序建立固定映射：`内容1 → 页面1`、`内容2 → 页面2`，依次类推。
4. 所有`N`个页面都创建并绑定成功后，才从页面1开始逐页串行上传和填写。不得同时触发两个文件选择器。
5. 某个页面准备完成后保持原标签页，不刷新、不导航、不关闭，也不在该页上传下一条视频。
6. 页面数量不足、标签页创建失败或任一页面无法确认时，不得开始快手上传；返回`快手需要 N 个上传页面，目前仅成功创建 M 个，尚未上传视频`。
7. 登录或旧内容提示阻止初始化时，先在当前页面完成对应的人工步骤；恢复后重新核对全部页面仍为空白且数量正确，再开始上传。

## 上次未发布内容

出现`还有上次未发布的视频，是否继续编辑？`或同义提示时：

- 内部固定选择`放弃旧内容`，不询问用户选择`继续编辑`还是`放弃`，也不把该项放进发布表单；
- 由于`放弃`会删除未发布数据，若自带浏览器在动作前要求确认，只请求用户确认执行本次放弃操作，不再让用户选择处理方式；
- 确认后只点击本页恢复提示中的`放弃`，不删除内容管理中的草稿或已发布作品。

## 标题、简介与作品描述映射

快手网页发布页当前只有一个`作品描述`编辑区，没有独立的`标题`输入框。按以下规则映射：

1. 只有标题：将标题原样填入`作品描述`。
2. 标题和简介都有：填入标题，换行后填入简介。两者完全相同时只填一次。
3. 简介中已包含标题且重复填写会明显产生双份内容时，暂停并说明映射问题，不擅自改写。
4. 不自动使用`智能文案`改写用户文本。

## 快速执行

恢复或重新连接时，先按`内容项 → 标签页`映射逐页读取上传区：出现目标文件名、上传进度、视频预览或编辑区时，不得再次选择文件。显示上传中则等待；显示已上传则从后续字段继续；只有绑定页面明确仍为空白上传区时，才允许为该页面选择对应文件一次。不得用快手全局“上次未发布的视频”代替页面映射。

1. 按 [file-injection.md](file-injection.md) 等待顶层页面动态出现`input[type="file"][accept*="video"]`。它当前为隐藏 input；不要把首次查询为空误判为不存在，也不要使用系统原生文件选择窗口。快手成为当前活动平台后，从此步骤到提交前核对完成都不操作其他平台。
2. 复用已经通过单平台验证的流程：注册 chooser，精确点击一次可见`上传视频`入口并设置文件；若页面实现允许真实 input 直接触发，也可优先使用真实 input。完成上传、平台必需处理和全部字段准备前不切换其他平台。
3. 文件选择成功后，页面允许时立即填写作品描述、标签映射的话题、封面和发布时间，不空等非阻塞检测。
4. 按上方映射规则原样填写标题和简介，再按下方话题流程添加标签。
5. 按 [cover-selection.md](cover-selection.md) 设置封面：有本地封面时上传并确保标题区域完整；否则识别候选视频帧中的标题区域，选择标题完整清晰的一帧。不自动开启`PK封面`。
6. 除通用字段外，快手页面其他设置一律保留当前默认值，不读取用户输入，也不主动修改。
7. 按 [schedule-policy.md](schedule-policy.md) 设置发布方式：立即发布时确认定时开关关闭且没有残留时间；定时发布时使用平台原生时间控件填写该内容对应的北京时间并核对回显。
8. 上传和平台必需处理完成后统一核对一次。`创作助手`中的标题建议、流量建议和非阻塞画质检测不必等待；只要`发布`按钮可用且没有错误，即可进入最终确认。

## 标签必须形成有效话题

快手话题在`作品描述`编辑区中添加。对用户给出的每个标签依次执行：

1. 去除输入开头已有的`#`，保留完整话题名称和顺序；预期词多于一个字时，拒绝把单字前缀当作话题。
2. 在作品描述末尾输入必要的空格，再输入`#`和完整话题名称。优先使用一次连续键入；必须分段输入时，在完整词输入结束前禁止等待或点击候选。
3. 先读取编辑区，确认完整的`#话题名称`已经出现，再等待候选列表。
4. 只点击规范化后与完整预期话题完全相等的候选项；禁止使用包含匹配、前缀匹配或默认点击第一项。`智能话题`不用于替换指定话题。
5. 点击候选后立即验证页面已出现独立话题标签、话题链接、已选项或其他明确绑定状态，且其完整文本与预期一致。普通`#话题名`文字不算成功。
6. 若出现`#农`、`#改`、`#生`等截断前缀，先删除错误标签和残留文本，再从干净状态用较慢的完整输入策略重试一次；不得在错误前缀后继续追加。
7. 重试后仍未形成完整话题时报告具体预期值与页面回显，停止该内容；不得误报成功或带着截断话题发布。

## 作者声明

不读取、不选择、不修改`作者声明`、`创作者声明`或同类声明，保持页面默认状态。若页面将该项设为必填且没有默认值，暂停快手并提示用户在当前页面处理；不得代选，也不得为了通过校验反复点击。

## 提交前内部核对

至少核对：

- 当前账号与用户指定视频；
- 上传和平台必需处理已完成；
- 作品描述中的标题、简介，以及与预期逐字一致的三条完整有效话题；
- 封面；
- 发布时间、页面阻塞错误和`发布`按钮状态。

核对通过后：单平台在`发布`按钮可用时请求自带浏览器动作前确认；多平台将快手标记为`等待统一发布确认`，不点击`发布`，随后按队列准备下一个平台。所有平台准备结束后只请求一次统一确认；用户确认后再按平台顺序点击一次`发布`。

## 结果验证

看到明确成功提示、页面跳转到成功结果，或在`内容管理`中找到作品描述、状态和时间相符的作品，才能报告`已发布`或`已提交平台定时发布`。只有提交结果不明时才进入内容管理核验；仍无法判断时报告`结果待确认，未自动重试`，不得再次点击发布。

格式、大小、时长、网络、验证码、风控或平台强制等待必须按页面处理，并用简明中文向用户说明。

选择文件发生 timeout 时继续停留在同一快手标签页并读取 input 的`files`：已上传或上传中则继续完成快手；页面和 input 都明确为空才可换一种策略一次；无法确认时返回`文件注入状态待确认，未自动重试`，暂停快手后再开始下一个平台。不得把多平台会话中的时序失败误报为快手、自带浏览器、登录或视频格式不兼容。

# 多平台执行状态、超时确认与断点恢复

本文件只规定执行机制，不改变统一字段、平台字段映射或 Codex 自带浏览器安全边界。多内容、多平台、恢复任务、任何 timeout、连接中断或页面状态不明确时必须读取并遵循本文件。

## 一、平台独立状态

每个平台维护独立的运行记录，至少包含：

- `platform`：平台名称；
- `item_index`：内容顺序；
- `content_type`：`视频`或`图文`；
- `media_names`：视频文件名或当前图文的图片文件名列表，不记录完整路径；
- `image_count`：图文预期图片数量；视频时为空；
- `publish_mode`：`立即发布`或`定时发布`；
- `scheduled_at`：定时发布时该内容对应的北京时间；立即发布时为空；
- `tab_id`：该平台该内容对应的自带浏览器标签页；
- `topics`：为该内容项确定的三条话题；
- `preallocated`：该内容的发布标签页是否已在上传前完成预分配；
- `phase`：当前页面确认的阶段；
- `last_action`：最近一次可能改变页面状态的动作；
- `last_action_outcome`：`已确认成功`、`已确认未发生`或`状态待确认`；
- `retry_count`：该动作已重试次数；
- `block_reason`：等待用户、浏览器阻止、页面错误或空；
- `result`：`执行中`、`成功`、`失败`、`待人工确认`、`浏览器阻止`或`结果待确认`。

批量任务另外维护`active_platform`和`active_item`。任何时候只能有一个活动平台和一条活动内容；可以提前创建或保留多个发布标签页，但页面导航、文件上传、上传等待、封面识别、字段填写和提交前核对都不得并行或交叉。

这些记录只用于当前任务的执行与汇总，不保存用户凭据或素材，不得用记录代替页面事实。一个平台失败、被阻止或等待人工确认时，只更新该平台状态；其他平台继续执行。

## 二、页面阶段

开始或恢复某个平台时，根据当前真实页面识别下列阶段。不得仅凭上一次对话、Agent 记忆或动作返回值推断：

1. `未打开发布页`
2. `发布页已打开`
3. `检测到旧内容`
4. `素材尚未上传`
5. `素材上传中`
6. `素材已上传`
7. `编辑页已就绪`
8. `标题已填写`
9. `简介已填写`
10. `标签已添加`
11. `封面已设置`
12. `发布方式已设置`
13. `等待统一发布确认`
14. `已点击发布`
15. `发布成功`
16. `发布失败`
17. `发布结果待确认`

一个页面可以同时满足多个已完成字段阶段。恢复时先识别视频或图文图片数量、顺序和编辑区，再逐项核对已完成字段，从第一个明确未完成的步骤继续；已完成步骤不得重复。发布方式与目标时间必须来自 [schedule-policy.md](schedule-policy.md)，恢复后不得改变用户选择。

## 三、timeout 后的后置状态确认

任何可能改变页面状态的自带浏览器操作发生 timeout 时，timeout 只代表控制端未及时收到完成结果，不代表网页动作失败。必须执行：

1. 记录平台、动作、目标字段或文件名和 timeout；不要立即报失败。
2. 不重复该动作，先等待当前页面恢复到可读取状态。
3. 检查自带浏览器连接、原标签页是否仍存在以及页面是否跳转。
4. 重新读取当前标签页；这是异常触发的状态读取，不计入正常阶段的读取次数。
5. 用与动作对应的页面后置条件判定：
   - 上传视频：出现文件名、上传进度、视频预览、编辑区或上传完成状态；
   - 上传图文图片：缩略图数量与顺序、上传进度或编辑区能证明全部图片已接收；
   - 上传封面：封面预览更新，或页面明确显示已应用的本地封面；
   - 标题/简介：控件当前值与用户输入一致；
   - 标签：出现平台认可的独立话题、标签卡片、链接或已选项；
   - 发布方式：立即发布时定时开关已关闭且无残留时间；定时发布时状态及该内容的北京时间回显一致；
   - 原创声明：可见选中状态明确；
   - 放弃旧内容：旧内容提示消失且空白上传状态出现；
   - 最终发布：明确成功提示、成功跳转，或内容管理中存在对应作品。
6. 后置条件成立：记为`已确认成功`，从下一步继续。
7. 页面明确显示动作没有发生：普通可恢复动作最多重试一次；重试前确认未出现重复内容。
8. 页面仍无法证明成功或未发生：记为`状态待确认，未自动重试`，停止该平台的副作用操作，但继续其他平台。

上传视频、上传图文图片、上传封面、放弃旧内容和最终发布属于高风险或难以撤销的动作。它们发生timeout且状态不明确时禁止重试。图文出现部分缩略图时不得重新上传整组；只有页面与input都明确为空时，才可按 [file-injection.md](file-injection.md) 更换一种上传入口一次。删除旧稿和最终发布仍须遵循动作前确认，不能沿用不相关授权。

填写标题、简介、标签、发布方式/时间或原创声明等普通动作，只有页面明确显示未发生时才允许重试一次；不得用重复追加的方式重试。标签重试前先确认没有已经生效的同名标签。

## 四、断点恢复

每次任务开始、自带浏览器重连或控制中断恢复后：

1. 找到或重新打开该平台发布页。
2. 读取一次完整页面，识别登录、旧内容、视频或图片缩略图、上传进度、编辑区和已填写字段。
3. 以页面事实重建平台阶段，不假定上一次动作成功或失败。
4. 已存在目标视频，或图文缩略图数量与顺序符合预期时，不重新选择素材。
5. 素材正在上传时等待页面进度或编辑区，不再次上传。
6. 只有页面明确处于空白上传状态且没有本任务素材，才允许选择文件。
7. 对标题、简介、标签、封面和时间分别比较当前状态；一致则跳过，不一致或缺失才处理。
8. 已点击发布但结果不明确时只核验结果，不再次点击发布。

页面无法确认现有视频或图片是否属于本任务时，不覆盖、不删除、不继续上传，标记`状态待确认，未自动重试`。检测到旧草稿或旧内容时使用对应平台流程；任何删除仍需动作前确认。

## 五、平台隔离与整个平台串行执行

### 准备阶段

1. 按用户填写的平台顺序建立平台队列，每个平台内按内容输入顺序建立内容队列，不按速度重新排序。
2. 平台无法在一个页面保留多条未提交内容时，有`N`个内容项就必须在任何素材选择前创建并确认`N`个发布标签页，把每个`tab_id`绑定唯一`item_index`。必须先完成页面池，再允许第一条内容上传；预分配失败只暂停该平台。
3. 将队首平台和首条内容设为`active_platform`、`active_item`。当前内容从页面进入、素材上传、平台必需处理、三条话题、字段填写、封面/首图、发布方式/时间设置到提交前核对完整执行；上传或处理中不切换到另一内容或平台。
4. 其他平台若不能在同一页面保留多条未提交内容，也按视频数量创建独立发布标签页，并把每个`tab_id`绑定到唯一的`item_index`。标签页逐个操作、逐个保留，禁止多个文件选择器同时运行。若要求预分配的平台没有创建足量页面，该平台不开始视频上传，保留已建页面并标记`发布页创建失败`，随后继续其他平台。
5. 当前内容只有达到下列状态之一才释放`active_item`并处理当前平台下一条内容；当前平台的内容队列结束后才释放`active_platform`：
   - `等待统一发布确认`：视频和字段均已准备完成，最终发布按钮可用；
   - `需要用户操作`：登录、验证码、旧稿确认或平台必填事实项等待用户；
   - `浏览器阻止`；
   - `失败`；
   - `结果待确认`。
6. 平台进入`需要用户操作`时记录断点，不让它长期占用活动位置；继续准备后面的平台。用户完成操作后，在当前队列末尾恢复该平台，并继续从真实页面状态执行。
7. 一个平台的失败、阻止或等待只更新该平台状态，不影响队列中的其他平台。
8. 任一平台若被自带浏览器站点安全策略限制，直接标记为`浏览器阻止`，显示`当前浏览器安全策略不允许 Agent 操作该页面`，然后继续下一平台；不无限重试或绕过。
9. 多平台失败而单平台正常时，按共享自带浏览器控制通道的交叉操作问题处理，禁止恢复并行上传或交叉填写；抖音、快手、视频号和百家号的预先建页仅分配页面，不代表并行执行。

### 统一确认与提交阶段

1. 队列中的所有视频或图文都完成上传与准备，或进入明确停止状态后，输出一次逐平台、逐内容摘要。在此之前不得请求最终发布审批。
2. 只对状态为`等待统一发布确认`的平台请求一次最终发布确认，明确列出将提交的平台；不要求用户逐个平台重复确认。
3. 用户确认后，仍按原平台顺序逐个平台执行最终发布。平台 A 的提交结果已明确为成功、失败或结果待确认后，才提交平台 B。
4. 某个平台提交结果不明时不得再次提交，但可以继续提交已包含在同一次确认中的后续平台。
5. 未包含在本次统一确认中的平台，恢复准备后必须重新请求确认，不能沿用之前的发布授权。

B站等待用户确认放弃旧内容时只标记 B站为`待人工确认`，随后按队列准备其他平台。任一平台登录过期、验证码、页面变化、失败或结果待确认，都不得中止其他仍可执行的平台。

## 六、页面读取频率

- 页面进入：完整读取一次，确定阶段和主要控件；不预读尚未轮到的平台。
- 连续填写：正常情况下连续处理标题、简介、标签、封面和发布方式/时间，不在每个输入后读取完整页面；允许读取局部控件状态验证有效话题、封面和时间。
- 异常读取：仅在 timeout、控件缺失、页面跳转、弹窗或状态不明确时重新读取完整页面。
- 准备完成：完整读取一次，核对关键内容、阻塞错误和发布按钮，但不点击发布。
- 提交结果：读取一次确认成功、失败或待确认；需要进入内容管理核验时只执行一次核验。

## 七、自带浏览器连接故障

连续 timeout 后先检查连接状态、当前标签页是否存在、页面是否仍可读取以及上一步是否实际完成。当前平台进入明确停止状态后才切换下一平台。只有明确确认自带浏览器整体不可用时，才提示用户重新打开 Codex 任务。

结束前必须输出每个平台和内容项的当前页面状态摘要。重新进入任务后按本文件的断点恢复流程从保留标签页或真实页面继续，不从头上传。

## 八、状态汇总

任务进行中和结束时按平台逐项输出，例如：

```text
抖音：编辑中
快手：上传中
小红书：待执行
B站：等待确认放弃旧内容
微博：待执行
视频号：浏览器安全策略阻止
百家号：浏览器安全策略阻止
```

最终结果归入：`成功`、`失败`、`待人工确认`、`浏览器阻止`、`结果待确认`。禁止用一段整体失败描述代替平台状态。

# 批次规划、累计账本与检查点

## 固定边界

一次任务只能有一个平台和一种内容来源。内容来源为`推荐内容`或`关键词搜索`；搜索模式只允许一个用户提供的关键词。六个数量输入都是任务总上限；每批固定上限如下：

| 项目 | 任务总上限 | 单批上限 |
| --- | ---: | ---: |
| 浏览 | 100 | 30 |
| 点赞 | 50 | 15 |
| 评论 | 50 | 15 |
| 收藏 | 30 | 10 |
| 关注 | 15 | 5 |
| 私信回复 | 5 | 5，仅最后一批检查 |

点赞、评论、收藏和关注的任务总上限不得超过任务总浏览数。所有互动数量都是上限，不是必须达到的目标。

## 自动拆批

内容批次数取以下值的最大值：

- `向上取整(总浏览 / 30)`；
- `向上取整(总点赞 / 15)`；
- `向上取整(总评论 / 15)`；
- `向上取整(总收藏 / 10)`；
- `向上取整(总关注 / 5)`。

私信回复不增加内容批次数，只在最后一个内容批次浏览完成后检查。先把总浏览数尽量均匀地分配到全部内容批次：每批先取`总浏览整除批次数`，余数从第一批起每批再加 `1`；因此各批相差不超过 `1`，且每批至少 `1` 条、不超过 `30` 条。然后按批次顺序为点赞、评论、收藏、关注分别分配初始配额，每批不得超过该动作单批上限、本批浏览配额和该动作剩余总额度。

例如总浏览 `100`、总评论 `50` 时生成四批浏览 `25/25/25/25`，评论初始配额 `15/15/15/5`；总浏览和总收藏均为 `30` 时生成三批浏览 `10/10/10`，收藏配额 `10/10/10`。这种顺序必须保证任意一个合法的内容互动总上限都能被各批容量容纳；若计算后仍有无法分配的额度，视为规划错误，禁止启动浏览器并重新计算，不能丢弃额度或生成零浏览批次。

每批互动有效上限为`本批计划配额`、`单批上限`、`任务剩余额度`和`本批已浏览数量`四者中的最小值；私信回复不受本批浏览数量限制。前一批没有用完的互动额度可以留到后续批次，但后续单批仍不得超过固定单批上限。不得回到已结束批次补充候选，也不得为用完额度降低标准。

## 耗时估计与进度

开始前根据总浏览量和各项互动上限给出宽范围估计，明确它不是完成承诺。可用每条真实浏览约 `20-45` 秒、每个准备并提交的互动约 `10-30` 秒估算，再考虑页面加载和用户确认时间。估算参数只用于用户提示，禁止据此设置固定停留、点击间隔或规律化行为。

每批开始时报告：`第 k/B 批`、本批浏览配额、本批各项有效上限、任务剩余浏览量和互动额度。每批结束时报告本批结果及累计进度。

## 累计任务账本

账本只保留在当前 Codex 任务上下文，不写入磁盘。至少维护：

- `任务配置`：唯一平台、内容来源、搜索关键词或空值、六个总上限、总批数；
- `批次状态`：批次号、浏览配额、各项有效上限、开始/结束状态；
- `累计计数`：浏览、候选、成功、已存在、待确认、用户取消、跳过、异常；
- `内容账本`：平台内容 ID 或规范化 URL、批次号、作者稳定标识、来源位置、理解置信度、搜索相关度或空值、各项互动状态、评论文本指纹和异常；
- `作者账本`：稳定账号 ID 或规范化主页 URL、来源内容、关注状态；
- `私信账本`：稳定会话标识、对方标识、最近入站消息指纹、回复文本指纹和发送状态。

跨批次去重以稳定 ID 或规范化 URL 为准。同一内容不得重复计入浏览，不得重复点赞、评论或收藏；同一作者不得重复关注；同一入站消息不得重复回复。标题、作者昵称、封面或文案只能辅助核对，不能单独作为延后提交对象的恢复依据。

只有已经记录稳定 ID 或规范化 URL、且提交时能够精确恢复的对象，才能进入延后互动候选。无法取得稳定定位信息的内容仍可计入有效浏览，但点赞、评论、收藏和关注均应跳过并记录`缺少稳定标识`。关键词搜索模式还必须按 [关键词搜索与相关度筛选](keyword-search.md) 记录搜索结果与相关度统计。

## 评论跨批次查重

评论审核必须比较当前批所有候选以及此前批次已生成、已取消、已成功或待确认的评论文本。主题词相同不等于重复，但相同开头、相同句式骨架、只替换少量名词或语义基本相同均视为高度相似。

高度相似时最多重写一次，并重新执行内容相关性和安全审核；仍相似或变得空泛时跳过。不得删除旧评论指纹来规避查重。

## 批次检查点与恢复

每批结束后在任务上下文建立检查点，包含：批次号、累计计数、任务剩余额度、最近处理的稳定内容标识、待确认动作和下一批号。页面刷新、标签页失效或人工验证恢复后，以检查点和页面明确状态修正账本，不从第一批重跑。

任何动作点击后结果不明确时记为`待确认`并占用相应任务额度；不得在恢复后重新提交。若整个 Codex 任务被关闭或上下文丢失，内存账本不可恢复，必须把后续工作作为新任务，并依赖页面明确状态避免重复操作。

## 候选调整与确认

系统确认前，用户可以删除候选或修改评论/私信文本。修改后的文本必须重新做相关性、安全性和跨批查重，并重新展示最终清单。系统确认只覆盖最终清单中的确切对象和完整文本。

确认后不得修改文本、增加候选或替换对象。用户拒绝确认默认结束任务；只有用户明确要求跳过本批继续，才把当前批候选记为`用户取消`并进入下一批。

# 微博状态、恢复与汇总

任务配置还必须记录`内容来源`和`搜索关键词或空值`。关键词搜索模式按共享的 [关键词搜索与相关度筛选](../../social-media-interact/references/keyword-search.md) 维护搜索结果位置、高/中/低相关和非内容结果计数；本文件中的推荐流状态与恢复名称相应替换为搜索结果页状态，停止条件以共享搜索规则为准。

## 任务状态与账本

在当前任务上下文中维护：唯一平台、六个任务总上限、总批数、当前批次、本批配额、任务剩余额度、本批与累计计数、连续无有效内容次数，以及微博、作者和私信账本。微博账本至少记录 mid/status ID 或规范化 URL、批次号、理解置信度、互动状态、评论指纹、发送状态和异常。

账本只保存防重复、精确恢复和汇总需要的最少信息，不写入磁盘，不保存账号凭据、完整页面或完整私信历史。

## 终态与幂等

点赞、评论、收藏、关注和私信回复使用：`未操作`、`候选`、`已存在`、`成功`、`待确认`、`用户取消`、`跳过`。

- `候选`等待当前批次统一确认；
- `成功`必须有明确页面后置状态，只计数一次；
- `已存在`不重复操作，也不计入本任务新增成功；
- `待确认`表示动作可能已发生，占用任务额度并禁止重试；
- `用户取消`表示本批确认被拒绝；
- `跳过`必须记录最少必要原因。

评论和私信发送尝试次数一旦点击必须保持为 `1`。任何超时都不直接等于失败；只有普通导航明确未发生时最多重试一次，所有互动点击后状态不明时不得重试。

## 异常与恢复

微博详情打不开、媒体失败、控件无法识别、评论编辑框验证失败或精确恢复入口不可用时，记录异常并处理下一项。登录过期、验证码、扫码或安全验证时停止为`等待人工验证`；用户处理后从最近批次检查点继续。

内置浏览器连接不可恢复、连续 5 次无法获得新有效推荐微博且一次刷新仍无效、页面结构不可靠或平台明确限制继续操作时，以`部分完成`停止。不绕过限制、不切换浏览器、不猜测结果。

## 汇总

每批报告批次号、本批配额、浏览与五类互动的候选/成功/已存在/待确认/用户取消/跳过/异常，以及累计进度和任务剩余额度。最终报告已完成批次、累计合计、未使用上限和主要跳过原因，不回显账号凭据、完整私信或无关页面数据。

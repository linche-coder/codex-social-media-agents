# 小红书推荐流执行流程

本文件默认描述`内容来源=推荐内容`。选择`关键词搜索`时，以共享的 [关键词搜索与相关度筛选](../../social-media-interact/references/keyword-search.md) 替代本文的推荐流入口、列表顺序、返回恢复和无新推荐终止规则；本文其余内容理解、候选、确认、提交和核验规则继续适用，文中的“推荐内容/推荐流”在这些环节视为当前搜索结果内容/搜索结果页。

## 执行方式：单平台自动拆批，每批确认后立即提交

小红书每个内容批次分为以下阶段：

1. `浏览与筛选`：完成本批配额的真实浏览，记录不超过本批有效上限的点赞、评论、收藏和关注候选，不进行公开互动。
2. `候选交接与调整`：把本批账本交回统一入口，完成跨批评论查重，并允许用户在系统确认前删除候选或修改文本。
3. `当前批次统一确认与提交`：统一入口对最终清单只做一次系统确认；确认后立即回到小红书提交并验证。
4. `批次检查点`：更新累计账本和任务剩余额度，再进入下一批。只有最后一批按上限检查已有入站会话并生成回复草稿。

浏览过程中不得为单篇点赞或评论打断用户。当前批次统一确认必须覆盖本批最终候选；确认后不得再按动作或单篇重复询问。用户拒绝时按统一入口规则结束任务，或在用户明确要求时跳过本批继续。

若浏览阶段因登录、验证码或安全验证暂停，恢复后从最近批次检查点继续，不从第一批重跑。

## 1. 准备与入口

1. 读取 `browser:control-in-app-browser` 的完整说明，按其规范加载随附的 `browser-client.mjs`，显式选择 `agent.browsers.get("iab")` 并完整读取内置浏览器文档。若统一入口已建立 `iab` 绑定则直接复用，不重新选择浏览器。
2. 只复用该 `iab` 绑定中已打开的小红书普通网页标签页；没有时在同一内置浏览器中新建标签页，打开小红书首页并进入推荐流。不得回退到 Chrome、Edge、网页搜索、平台 API 或其他浏览器工具。
3. 确认当前是推荐流且页面可交互。若未登录，停在登录页并报告`等待用户登录`；验证码、扫码或安全验证按`等待人工验证`处理。
4. 复用统一入口建立的累计任务账本和当前批次检查点。状态只保留在当前任务上下文，不写入本地文件。

## 2. 获取下一篇唯一内容

按推荐流顺序打开下一篇未处理内容。优先使用页面提供的笔记 ID 或规范化笔记 URL 作为`稳定内容标识`；没有稳定 ID 或规范化 URL 时，可用可见作者与标题组合形成仅用于本次浏览去重的临时标识，但该内容不得进入延后互动候选。

- 已在账本中的内容：关闭或返回推荐流，继续下一篇，不增加浏览数。
- 打开即报错、内容不存在或完全无法加载：记录异常，返回推荐流，不增加有效浏览数。
- 推荐内容模式不使用搜索替代推荐流；关键词搜索模式不使用第二个关键词、指定账号或外部链接补足数量。

## 3. 真实浏览与内容理解

### 视频

确认视频处于播放状态，并观察播放进度确实向前推进。按共享视频预览规则使用页面支持的最高倍速，每条实际预览最多 `60` 秒；结合可见画面、字幕、标题、正文和话题理解主题与主要表达。

视频提前结束或已足以理解时可以更早停止，不要求完整播放，也不为凑满一分钟等待；禁止只读标题或封面后马上判断。达到预览上限后信息仍不足时，按共享规则只读参考当前视频已有评论；仍无法形成可靠理解时标为低置信度。

### 图文

打开内容页，阅读标题和正文，浏览主要图片或轮播页，并按内容长度适当滚动。不要只看封面。图片打不开、正文不足且无法理解时标为低置信度。

### 内部理解记录

为每篇形成最少必要的内部记录：

- `内容类型`：视频或图文；
- `主题`与`主要表达`；
- `可见依据`：实际内容、字幕、正文、标题、话题中真正使用到的信息；
- `理解置信度`：高、中、低；
- `是否广告或信息过少`；
- `互动价值`与跳过理由。

优先级为：实际视频或图文内容 > 字幕 > 正文 > 标题 > 话题。完成这一步后才把`已浏览 +1`，并进行本篇的点赞与评论候选判断。

## 4. 点赞候选筛选

在`本批点赞候选数 < 本批点赞有效上限`且任务点赞仍有剩余额度时，内容有信息价值、质量较高、观点有意思或有讨论价值，可以列为点赞候选；点赞不必表示完全赞同。低置信度、纯广告、无法理解或明显低质量内容默认不列入候选。

筛选顺序：

1. 读取点赞控件当前状态。
2. 已点赞则记为`已存在`，不列入候选。
3. 未点赞且值得点赞时记为`点赞候选`，浏览阶段不点击。
4. 候选达到本批点赞有效上限后继续浏览，但不再新增点赞候选。

## 5. 评论候选生成

仅在`本批评论候选数 < 本批评论有效上限`、任务评论仍有剩余额度且内容适合讨论时考虑评论。

1. 先检查当前任务账本和页面可见评论，确认没有对该内容提交过评论。
2. 按 [评论生成与审核](comment-policy.md) 生成并审核评论；不合格时最多重写一次，仍不合格则跳过。
3. 审核通过后记为`评论候选`并保存会话内指纹，浏览阶段不填写、不提交。
4. 候选达到本批评论有效上限后继续浏览，但不再生成新评论候选。

发现页面已有本账号评论时记`已存在`并跳过，不新增本任务成功数。

## 6. 收藏、关注与私信回复候选

按 [收藏、关注与私信回复](../../social-media-interact/references/extended-interactions.md) 执行。浏览当前笔记时独立判断收藏价值和作者持续关注价值，分别按内容 ID 与作者账号 ID 去重；浏览阶段不点击收藏或关注。

只有最后一批达到本批浏览配额后，若`私信回复任务剩余额度 > 0`，才只读进入小红书消息入口，按未读优先、最近会话次序检查已有入站私信并生成不超过剩余额度的回复草稿。不得主动给笔记作者发私信，也不得在候选阶段输入文本。

## 7. 本批候选交接、确认与提交

达到本批浏览配额后，把以下信息交回 `$social-media-interact`：

- 点赞候选的最少必要内容标识或主题；
- 每条评论对应的内容标识或主题；
- 每条拟发布评论的完整文本；
- 收藏候选的内容标识、关注候选的作者标识；
- 私信候选的会话和对方标识、最少必要上下文及完整回复文本；
- 五类互动候选数量、本批有效上限与任务剩余额度；
- 浏览完成度、异常和跳过原因。

平台流程把候选交回统一入口，由统一入口完成跨批查重、用户调整和当前批次的一次系统确认。只有收到本批确认结果后，才按推荐流中的原顺序逐项执行：

1. 重新打开候选内容并核对内容标识。
2. 依次处理点赞和收藏；每个控件都先确认当前未生效，再单击一次并验证后置状态。
3. 按作者账本处理关注；只有作者身份匹配且当前明确未关注时才单击一次。
4. 评论前再次检查本任务账本和页面，提交统一确认中展示的原评论文本。
5. 内容互动结束后进入正确会话，按私信状态机提交已确认的原回复文本。
6. 某个候选异常不终止其余已确认候选，但必须记录异常。

确认后不得为动作或单篇再次请求确认。用户拒绝当前批次统一确认时，把本批候选记为`用户取消`并按统一入口规则结束或显式跳过本批。

### 评论编辑与提交状态机

评论必须依次经过`折叠态`、`展开态已验证`、`文本已核对`、`发送已点击`和`结果已验证`。不得跳过中间状态，也不得把 DOM 中存在的编辑元素当作展开成功的证据。

#### A. 从折叠态进入展开态

1. 在当前笔记详情容器内重新核对内容标识，并将该容器作为本次评论定位的作用域。不得定位到推荐流卡片、其他笔记或页面外层的评论控件。
2. 在该容器内定位当前可见且可交互的`说点什么…`评论入口。该元素仅是展开入口，不是最终编辑框；即使附近或 DOM 中已经存在`#content-textarea`、`contenteditable="true"`或类似元素，也不得直接填充。
3. 点击评论入口一次，使评论区尝试进入展开编辑态。
4. 点击后立即丢弃折叠态页面快照、元素引用和定位器，重新读取 DOM，并重新定位当前笔记详情容器、评论编辑区域、编辑框、`发送`按钮和`取消`按钮。
5. 只有同时满足以下条件，才记为`展开态已验证`：
   - 当前内容标识与点击入口前完全一致；
   - 展开的评论区域内存在一个真实、可见且可交互的编辑框；
   - 同一展开区域内的`发送`和`取消`按钮均可见；
   - 编辑框能够获得焦点并接受输入，不是隐藏、被遮挡、禁用或仅存在于 DOM 的占位元素。

存在多个编辑元素时，只能选择当前笔记详情容器内、当前展开评论区域中可见且可交互的那个。优先依据可见状态、可交互状态和展开后的 UI 层级定位，不使用固定屏幕坐标。

上述任一条件不满足时，不得输入、不得点击发送；将该候选记为`评论编辑态展开失败`并记录页面异常，然后处理下一个已确认候选。

#### B. 输入与发送前核对

1. 仅向`展开态已验证`后重新定位得到的真实编辑框填入评论原文，不得复用折叠态取得的元素或定位器。
2. 输入后重新读取展开评论区域的状态，确认编辑框中可读取的文本与当前批次确认时展示的评论原文逐字一致，并确认`发送`按钮可见、可交互且已启用。
3. 点击发送前再做一次最终核对：当前内容标识未变化、账本中的评论原文未变化、编辑框文本完全一致、发送按钮仍处于启用状态。
4. 任一核对失败时不得提交；记录具体异常并处理下一个候选。

#### C. 单次发送与结果验证

1. 最终核对通过后，把该内容的评论`发送尝试次数`记为 `1`，再点击`发送`一次。无论点击返回、超时或页面如何变化，同一候选都不得再次点击发送。
2. 点击后重新读取页面状态。仅以下任一权威信号可记为`评论成功`：本账号评论明确出现在当前笔记中、页面明确提示发送成功，或平台提供其他等价的明确成功状态。
3. 如果点击后意外返回推荐流、详情页关闭、内容标识变化、页面超时，或结果无法从权威信号确认，记为`评论待确认`并禁止重试。
4. 页面明确拒绝发送或明确报告失败时，记录页面异常并继续下一个候选；不得为了补足评论上限重新发送该评论。

## 8. 评论对象恢复

评论阶段优先使用账本中的笔记 ID 或规范化 URL 重新打开。若直接入口失效，可进入本账号点赞列表或收藏列表作为恢复入口，但只允许处理与任务账本 ID 精确匹配的候选；不得按标题、作者或封面模糊匹配，也不得处理旧点赞或旧收藏内容。连续 5 次加载仍找不到目标时记为`评论对象不可恢复`并跳过。

评论候选不因定位需要而自动变成点赞或收藏候选。只有它本身满足标准、在对应上限内且已经纳入当前批次统一确认时，才允许先点赞或收藏再从列表恢复。

## 9. 停止条件

当前批正常浏览结束条件为`本批已浏览 == 本批浏览配额`。为避免页面故障造成无限循环，连续 5 次无法获得新的有效内容时，进行一次推荐流刷新或重新进入；恢复后仍连续 5 次失败则以`部分完成，推荐流无法继续`停止，并输出已完成统计与最近错误。不得无限重试。

本批候选提交完成、用户拒绝当前批次统一确认或本批没有候选时，把结果和检查点交回统一入口。仅当全部批次完成或安全停止条件成立时结束整个任务；不得回到旧批次补数。
